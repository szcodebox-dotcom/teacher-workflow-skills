# 工作流封装

把教师反复使用的方法封装成独立、可读取、可验证的 Skill。先确定触发任务、必要输入、完整产物、判断条件和证据边界。正常任务与关键缺输入分别检查；没有真实用例时使用明确标注的合成例子，不能把模拟输出称为课堂实测。

## 从方法到输入输出

保留老师原方法中有效的步骤，补足缺少的交付和核对环节。关键题面、评分依据或真实数据不足时说明缺口，不编造成绩和教学效果；目录命名、样例构造等常规选择直接完成。

只有重复计算、文件转换或一致性核对确有必要时才写脚本。资源使用相对路径，脚本可独立运行；不依赖作者电脑、原仓库根目录或未安装的其他技能。

## WorkBuddy 包结构

独立技能以小写字母、数字和连字符命名，优先使用 `teacher-` 前缀，目录名与 frontmatter 的 `name` 一致。交付 `SKILL.md`、`SUMMARY.md` 及确有用途的 `references/`、`examples/` 或 `scripts/`；简单文本方法无需添加空目录和脚本。

WorkBuddy 的 `SKILL.md` frontmatter 包含 `name`、用途与触发描述 `description`、`description_zh`、`description_en`、`version` 和 `author`；需要列表展示时补 `display_name` 和 `display_name_en`。正文写输入、处理、产物、核对与修正；细长数据契约放参考文件并链接。自动发现保留默认，只有用户要求手动触发时才设置相应平台字段。

用户要的是独立技能时交付上述目录。用户明确要专家包时，另按当前 [WorkBuddy 专家格式](https://open.workbuddy.cn/docs/expert) 封装 `.codebuddy-plugin/plugin.json`、`agents/主专家.md`、头像和 `skills/`。Agent 的工具权限由 WorkBuddy 提供，不自行声明 `tools`，也不把 Codex 专用 `agents/openai.yaml` 写成 WorkBuddy 必需文件。

## 验证与交付

1. 核对 frontmatter、资源引用、独立依赖和真实产物；技能包需可从解压目录读取，不能只在作者电脑有效。
2. 对正常任务检查完整题干、答案、评分或具体输出；对关键缺输入检查没有伪造事实，且保留可完成部分与下一步。
3. 有脚本就实际运行并保存输入、输出及检查结果；复杂课件还须说明实际视觉核验范围。格式通过不能证明教学效果。
4. 自主撰写说明、例子和代码；来源题保持授权和出处，通用学科知识与接口不声称独占原创。

包保存到用户指定位置；未指定时放当前工作区。完成已经授权的制作和可逆修正，报告实际文件与验证范围。安装、消息发送和外部发布沿用当前任务授权，不能因封装专家而扩展权限。

完整合成例子见 [离堂检测闭环](references/worked-example.md)。
