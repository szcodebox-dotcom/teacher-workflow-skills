# 学情分析

把成绩转为可核查的教学证据。得分能够说明本次任务表现，不能单独说明错误原因、学习能力或学生态度。

## 输入与口径

接收 CSV 长表，必需列为 `exam_id,student_id,question_id,knowledge_point,score,max_score`。格式、缺失处理和计算定义见 [数据口径](references/data-contract.md)，运行示例见 [完整示例](references/worked-example.md)。若输入是总分表，只生成总分统计，并写明无法定位知识点；不得分摊总分伪造小题成绩。

- `student_id` 使用学号或化名；年级、学科、题目内容用于解释结果，缺少时可先完成数值报告，但暂不编写具体学科讲评。
- 知识点映射和满分必须来自试卷或教师提供的资料。缺少这些计算关键字段时列出缺项，保留已能完成的核对结果，不推测填补。
- 空分代表未取得评分记录，零分代表已评分且得零分。没有任何数据行的学生不在可见名单内，不能估算其人数。
- 若要判断跨测验变化，先取得考试范围、题目要求、评分与参测名单的可比性说明。总分除以满分仅统一展示尺度，不能自动建立难度等值。

## 执行

1. 核对列、重复键、分值边界、同一题满分和知识点是否一致。任何会改变计算口径的错误都应先修正；记录原始行号与问题，不静默删行。
2. 在已安装的本技能目录下运行标准库脚本：

   ```bash
   python3 <本技能目录>/scripts/analyze_scores.py <成绩CSV路径> --output-dir <报告目录>
   ```

   尖括号代表调用时按实际路径替换的命令参数。复现包内样例时，可直接从本技能目录执行：

   ```bash
   python3 scripts/analyze_scores.py examples/scores.csv --output-dir /tmp/teacher-learning-demo
   ```

3. 用 `report.json` 中的分子、分母与人数复核 Markdown 报告。整卷均分、通过率和优秀率只使用该卷全部题目有评分记录的学生；部分记录和全未评分记录分别报告。知识点得分率使用有效小题的累计得分除以累计满分，同时披露覆盖和样本数。
4. 从知识点、题目与作答材料中挑选教学优先项。只有得分时写“需要观察的表现”；有学生作答、访谈或课堂记录时，才列出证据支持的可能错因，并区分未核实假设。
5. 每个优先项给出可执行的复测：要观察的操作、题型、评分规则、实施窗口和调整条件。不要把全班后几名知识点强行当作薄弱点；只有一个知识点时只报告一个。

## 多次测验

脚本默认按卷描述，不输出提升/下降结论。教师提供对齐说明后，可加 `--aligned-exams` 生成共同知识点的描述性差值；该参数只是记录调用者的对齐声明。不同满分的原始总分永远不作直接差值。即使范围对齐，题目难度、评分、学生名单和缺失比例变化仍应列为限制，不能声称教学干预导致进步。

## 交付

交付 `report.json`、`report.md` 和简短教学跟进表。跟进表列出“证据及分母 → 待验证问题 → 练习/复测 → 判定条件”。保留数据质量检查与限制，展示学生记录时不公开排名。用户只要求数值统计时，无需扩写教学建议；若需两周班级安排，可将报告、试卷内容与可用课时交给 `$teacher-class-action-plan`。

报告中的阈值是本次统计设置；默认通过阈值为 60%，优秀阈值为 85%，可用 CLI 参数改变。它们不能替代学校规定，更不能成为固定能力标签。
