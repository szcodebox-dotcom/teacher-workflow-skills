# 工作流封装

将老师的方法变成能独立调用、按输入完成产物的技能包。真实用例帮助检验流程；不足时使用明确标注的合成用例验证结构与行为，不把“有几个案例”当成封装门槛。

## 从方法到契约

提取用途、触发任务、必要输入、完整产物、分支判断和不能推断的事实。有现有流程先保留有效步骤；用户要求设计新流程时可原创设计，但注明其验证范围。影响教学事实或正确答案的关键材料缺失时列明缺口，不能补造真实课堂数据；命名、文件结构和样例构造可直接决定。

把不必要的通用提示删去，保留会改变执行结果的条件。例如“空分与零分区分”“没有题面不推测知识点”“公开稿只含聚合证据”。判断由模型完成即可的开放任务无需添加脚本；重复计算、转换或一致性核对可提供可运行脚本。

## 包结构与发现

技能 ID 使用小写字母、数字和连字符，少于64字符；自建教学技能优先 `teacher-` 前缀，避开 `find-skills`、`skill-creator` 等已有通用名称。目录与frontmatter的`name`一致。

交付必需的 `SKILL.md`、用户可读的 `SUMMARY.md`、`agents/openai.yaml`，以及确有用途的示例/脚本/参考。包内路径均使用相对路径，不能依赖作者本机、仓库根目录或未安装技能。必要外部工具应写出环境要求和缺少时的处理，不声称能力已运行。

`SKILL.md` frontmatter写 `name`、简明`description`、`metadata.version`；描述同时说明产物和触发情境，避免吸引无关任务。正文保留实际执行顺序、关键输入、完整输出和证据边界。细长数据契约与完整例子放在references中，并从入口说明何时读取。

`agents/openai.yaml`的字符串加双引号。`interface.short_description`为25–64字符，`default_prompt`必须出现`$技能ID`。默认可自动选择；只有用户明确要求仅显式调用时设置`policy.allow_implicit_invocation: false`，不把一般数据处理都变成确认流程。

摘要列出用途、输入、产物、运行条件、限制、包内资源与验证状态。操作必须有输入→处理→输出→检查→必要时修正的闭环；交付文件不能残留待填内容或以“草稿”替代最终包。

## 验证与原创边界

1. 核对命名、frontmatter、引用路径与界面配置；若环境中提供标准验证器可运行，否则完成等价检查并记录实际检查方式。结构通过不等于教学有效。
2. 至少选择一个正常任务与一个关键边界进行行为验证。真实输入可脱敏后使用；没有真实案例时构造最小合成案例，给出实际输出及核对结果。不要要求固定数量的真实案例，也不要把模拟使用写成课堂实测。
3. 脚本实际运行，测试有意义的计算/输出/失败行为；教学内容核对题目、答案、评分与用时。失败时修正包并重跑相关验证。
4. 自行撰写流程说明、示例和代码，不复制他人的技能正文。提供的外部材料只按授权和来源范围使用；通用格式规范、学科事实、软件接口不声称独占原创。审查可以说明未发现复制段落与原创创作过程，不能凭局部检索承诺查遍所有出版物。

## 交付

把完整目录保存到用户指定位置；未指定时在当前工作区生成可检查技能包，不擅自全局安装或发布。报告实际版本、文件、验证输入和结果、剩余限制。用户已授权的本地修正可继续完成，不为常规可逆操作增加确认点；外部发布与发送沿用用户已有授权。

完整封装示例见 [离堂检测闭环包](references/worked-example.md)，其中的验证全部明确标注为合成检查。
